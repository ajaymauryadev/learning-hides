# Topic 6 — API kya hai?

## Aaj ka exact objective

Aaj **API** ka foundational mental model samajhna hai: do software parts ek defined
interface ke through kaise interact karte hain. Request/response Topic 7 mein aur
HTTP/REST implementation Phase 6 mein aayegi. Aaj endpoint ya code create nahi hoga.

## Prerequisite recap

```text
User -> client -> server/backend -> database
```

Client ko server ke internal code ya database structure directly operate nahi karna
chahiye. Use allowed operations ke liye ek clear interaction boundary chahiye. Yeh
boundary API provide kar sakti hai.

## Full form aur simple definition

**API = Application Programming Interface**

**API rules aur defined operations ka interface hota hai jiske through ek software
component doosre software component ki functionality ya data use kar sakta hai,
bina uske internal implementation ko directly control kiye.**

Simple words:

> API software ke liye batati hai: tum kya maang sakte ho, kaunsi information deni
> hogi, aur kis type ka result mil sakta hai.

## Restaurant analogy

```text
Customer       = client
Menu           = available operations ka interface
Order details  = required input
Kitchen        = hidden internal implementation
Dish/error     = result
```

Customer menu se supported item order karta hai. Use kitchen ke tools aur internal
steps directly operate nahi karne padte. Isi tarah API consumer ko internal code
jaane bina supported operation use karne deti hai.

Menu analogy limited hai: real API exact formats, rules, authentication aur errors
bhi define kar sakti hai.

## TaskForge API example

Conceptual task-create capability:

```text
Available operation: Create a task
Required information: Project identity aur task title
Optional information: Priority ya due date
Possible success: Created task ka safe result
Possible failure: Missing title, no permission, ya project not found
```

Client ko database mein direct record insert nahi karna. Woh TaskForge ki supported
API operation use karega; backend trusted rules enforce karega.

Actual URL, HTTP method, status code aur JSON body abhi define nahi kiye gaye.

## API as a contract

Contract ka simple meaning hai agreed expectations.

API contract commonly batata hai:

- kaunsa operation available hai;
- operation ko kya input chahiye;
- input ka expected format kya hai;
- success par kya result milega;
- failure kis form mein mil sakta hai;
- authentication/permission required hai ya nahi;
- operation ka possible side effect kya hai.

Example: agar API task title ko string expect karti hai aur client number bhejta hai,
to contract follow nahi hua.

Detailed API-contract design Topic 200 mein aayega. Current
`notes/API_CONTRACT.md` actual implemented behaviour hi store karega, future guesses
nahi.

## API internal implementation ko hide karti hai

Client ko generally yeh nahi jaana chahiye:

- TaskForge ki files kaunsi hain;
- database query kaise likhi gayi;
- password kaise hash hua;
- internal service kaunsi function call karti hai.

Client contract follow karta hai. Server internal implementation change kar sakta
hai, jab tak promised API behaviour compatible rahe.

Is idea ko **abstraction** kehte hain: consumer ko required interface dikhao, hidden
details manage karne ki responsibility provider ke paas rakho.

## API sirf web API nahi hoti

API broad concept hai:

- JavaScript array ka `.map()` method ek programming interface ka example hai.
- Operating system programs ko file operations ke interfaces deta hai.
- Web API network ke through software systems ko interact karwa sakti hai.

TaskForge learning project mein hum mainly backend **web API** banayenge. HTTP aur
network details later aayengi.

## API, UI aur CLI

- **UI:** humans ke liye visual/interactable interface.
- **CLI:** humans/programs ke liye text-command interface.
- **API:** software components ke interaction ka programming interface.

Ek UI internally API use kar sakti hai, lekin UI khud automatically API nahi hoti.

## API, backend, server aur database same nahi

- **API:** supported interaction boundary/contract.
- **Backend:** hidden logic, rules aur coordination.
- **Server:** clients ko serve karne wala software role/process.
- **Database:** persistent data store.

TaskForge mein conceptual relation:

```text
Client -> API boundary -> backend/server logic -> database
Client <- API result   <- backend/server logic <- database result
```

## API kyun useful hai?

### Clear boundary

Client ko supported operations aur expectations pata rehti hain.

### Separation

Frontend internal database/code details se tightly coupled nahi hota.

### Reuse

Web app, mobile app aur approved integration same capabilities use kar sakte hain.

### Security enforcement point

Backend API boundary par authentication, authorization aur validation enforce kar
sakta hai. API hona automatically secure hone ki guarantee nahi; correct security
implementation required hai.

### Independent development

Clear contract hone par frontend aur backend teams coordinated way mein work kar
sakti hain.

## Public aur private API ka basic idea

- **Public API:** external developers/consumers ke documented use ke liye exposed.
- **Private/internal API:** organization ya application ke controlled components ke
  beech use hoti hai.

Public ka matlab authentication-free nahi hota. Private ka matlab automatically safe
nahi hota. Access control separately required ho sakta hai.

## Success aur failure

### Successful use

Client supported operation ko correct input ke saath use karta hai; provider
contract ke according result deta hai.

### Invalid input

Required information missing/wrong format ho to API safe validation failure deti hai.

### Unauthorized operation

Client operation jaanta hai, lekin current user allowed nahi; backend reject karta
hai.

### Contract mismatch

Client old expectation use kare aur provider incompatible behaviour de, integration
break ho sakti hai. Isliye documentation, compatibility aur versioning important
hote hain.

### Internal failure

Provider ke andar failure aaye to internal secret/stack detail expose kiye bina safe
failure result dena chahiye.

## Common misconceptions

1. **"API matlab backend."**  
   API backend ki exposed interaction boundary ho sakti hai; complete backend nahi.

2. **"API matlab URL."**  
   Web API operation mein URL ho sakta hai, lekin API mein input, output, rules aur
   errors bhi include hote hain.

3. **"API directly database hai."**  
   API interaction boundary hai; backend database operation coordinate kar sakta hai.

4. **"API sirf frontend use karta hai."**  
   Mobile apps, CLIs aur other services bhi API consumers ho sakte hain.

5. **"API key ho to API secure hai."**  
   Security validation, authorization, secret handling, rate limiting aur other
   controls par depend karti hai.

6. **"Internal code badla to client bhi badlega."**  
   Agar contract-compatible behaviour same rahe, internal implementation badal sakti
   hai without client change.

## Interview question with Hinglish answer

**Question:** API kya hai aur TaskForge mein kyun use hogi?

**Answer:** API ka full form Application Programming Interface hai. Yeh defined
operations aur rules ka interface hota hai jiske through ek software component
doosre ki functionality ya data use karta hai bina internal implementation directly
control kiye. TaskForge frontend API ke through task create ya read jaise supported
operations use karega, aur backend validation, permissions aur data work handle karke
defined result dega.

## Easy-English minimum interview answer

**API stands for Application Programming Interface. It is a defined contract that
allows software components to communicate and use each other's functionality without
knowing the internal implementation. In TaskForge, clients will use the API to perform
operations such as creating or reading tasks.**

### Even shorter version

**An API is a contract that allows software applications or components to
communicate with each other.**
